4. **Numeração de migrations** — PR-A ocupa 0004 (`adapter_name`), PR-B ocupa 0005-0008. M7.6 (Agent Studio) ajusta sua numeração pra 0009+.

### A.2 Interface `AgentAdapter` (stateful)

```ts
// packages/shared/src/types/adapter.ts
export type AdapterName =
  | 'claude-oauth-local'
  | 'claude-api-key-local'        // futuro (M9)
  | 'claude-oauth-remote-docker'; // futuro (M10)

export type SpawnContext = {
  agent: Agent;
  oauthToken: string;             // M9 substitui por discriminated union AuthCreds
  dbPath: string;
  permissionsDir: string;
  eventsDir: string;
  userDataDir?: string;
  mcpServerJsPath?: string;
};

export type ParsedEvent = { /* ...existing shape from stream-parser... */ };
export type UsageEstimate = {
  input: number;
  output: number;
  cache_read: number;
  cache_creation: number;
};

export interface AgentAdapter {
  readonly name: AdapterName;
  readonly agentId: string;

  start(): Promise<void>;
  sendInput(text: string): void;
  onEvent(cb: (e: ParsedEvent) => void): () => void;  // returns unsubscribe
  onStderr(cb: (line: string) => void): () => void;
  onExit(cb: (code: number | null) => void): () => void;
  kill(): void;
  isAlive(): boolean;
  getUsage(): UsageEstimate;
  getCurrentAction(): string | null;  // pro UX polish do PR-C
}

export interface AgentAdapterFactory {
  readonly name: AdapterName;
  create(ctx: SpawnContext): AgentAdapter;
}
```

**Lifecycle:**
1. Orchestrator chama `factory.create(ctx)` → retorna instance.
2. Subscribe a eventos via `onEvent/onStderr/onExit` (retornam unsubscribe).
3. `await adapter.start()` → spawn process + setup stdio.
4. `adapter.sendInput(text)` durante turn.
5. Em fire/kill: `adapter.kill()` → cleanup interno (rm tmp dirs etc).
6. Em restart: `kill()` + remove do Map + `factory.create(ctx)` novo.

**`MAX_CONCURRENT_AGENTS` check** (atual: 4) move pra `ensureAdapter()` no `lifecycle.ts`, antes do `factory.create()`. Não fica dentro do adapter (regra é do orchestrator, não da implementação de execução).

### A.3 `lifecycle.ts` reduzido (~80 LOC)

```ts
import type { AgentAdapter, SpawnContext } from '@prospero/shared';
import { adapterRegistry } from './adapters/index.js';

const adapters = new Map<string, AgentAdapter>();

export const MAX_CONCURRENT_AGENTS = 4;

export const activeAdapterCount = (): number =>
  [...adapters.values()].filter(a => a.isAlive()).length;

export const ensureAdapter = async (ctx: SpawnContext): Promise<AgentAdapter> => {
  const existing = adapters.get(ctx.agent.id);
  if (existing?.isAlive()) return existing;

  if (activeAdapterCount() >= MAX_CONCURRENT_AGENTS) {
    throw new Error(
      `Max concurrent agents (${MAX_CONCURRENT_AGENTS}) reached. Kill one before spawning a new agent.`
    );
  }

  const name = ctx.agent.adapterName ?? 'claude-oauth-local';
  const factory = adapterRegistry[name];
  if (!factory) throw new Error(`Unknown adapter: ${name}`);

  const adapter = factory.create(ctx);
  adapters.set(ctx.agent.id, adapter);
  await adapter.start();
  return adapter;
};

export const getAdapter = (agentId: string): AgentAdapter | undefined =>
  adapters.get(agentId);

export const removeAdapter = (agentId: string): void => {
  adapters.delete(agentId);
};

export const restartIfRunning = async (
  agentId: string,
  ctx: SpawnContext
): Promise<AgentAdapter | null> => {
  const existing = adapters.get(agentId);
  if (!existing?.isAlive()) return null;
  existing.kill();
  adapters.delete(agentId);
  return ensureAdapter(ctx);
};
```

Helper `restartIfRunning` é usado por `agents:set-model/set-role/set-system-prompt` IPC handlers (já existem em `orchestrator-handlers.ts` desde M7-C). Refactor preserva semântica.

## PR-B — 4 migrations + repositórios

### B.1 Migration 0005 — `issues.identifier` humano

```sql
-- 0005_issue_identifier.sql
ALTER TABLE projects ADD COLUMN slug TEXT;
ALTER TABLE issues ADD COLUMN issue_number INTEGER;
ALTER TABLE issues ADD COLUMN identifier TEXT;

CREATE UNIQUE INDEX idx_issues_project_number
  ON issues(project_id, issue_number);
CREATE INDEX idx_issues_identifier
  ON issues(identifier);
```

**Backfill** via script TypeScript (`apps/main/src/db/migrations/scripts/backfill-issue-identifiers.ts`) que roda pós-migration SQL:
1. Para cada project: derivar slug se nulo (`UPPER(SUBSTR(REPLACE(name,' ',''),1,6))`); resolver colisão appendando `-2`, `-3` etc.
2. Para cada project: pegar issues ordenadas por `created_at`, numerar `1..N`.
3. Setar `identifier = '${slug}-${issue_number}'`.
4. Tornar `issues.issue_number` e `issues.identifier` NOT NULL via 2ª ALTER (SQLite limitation: precisa recriar tabela ou usar `STRICT` workaround).

**Decisão simplificada:** manter NULL-able no schema; aplicação enforces NOT NULL via Zod + repo. Migration zero-downtime.

**Repo changes:**
- `IssuesRepository.create(input)` faz transaction: `SELECT MAX(issue_number) WHERE project_id = ?` → `+1` → INSERT com `issue_number` e `identifier` calculados.
- Atomic: better-sqlite3 transaction garante (single-writer; sem race).
- Slug update: novo IPC `projects:set-slug(projectId, slug)` (validação alfanum + uppercase). Default na criação: derivado de `name`.

**Display update — onde aparece identifier vs UUID:**
| Local | Antes | Depois |
|---|---|---|
| `IssueDetailModal` header | nada | `BACKEND-7 · ${title}` |
| `IssueCard` kanban | só title | `BACKEND-7 · ${title}` |
| Sidebar Issues list | só title | `BACKEND-7 · ${title}` |
| MCP `list_issues` response | UUID | identifier (+ UUID em campo separado pra refs) |
| MCP `update_issue` aceita | UUID | UUID **ou** identifier (helper resolve) |
| `inbox_items.payload_json` "agente assigned to {issueId}" | UUID | identifier |
| `issue_events.actor_name` ref | UUID | identifier |
| Activity stream (M7.7 futuro) | n/a | identifier |

**System prompt impact:** agentes referenciam por identifier nas mensagens. Reduz token noise (UUID 36 chars → 9 chars). Bloco no `preamble.md`:
> "Use the human identifier (e.g. `BACKEND-7`) when referring to issues — not the UUID. The MCP tools accept either."

## PR-C — UX polish + E2E setup + security/VPS docs

### C.1 Current action granular

Hoje `agents.status` é binário-ish (idle | thinking | working | waiting | error). Sidebar mostra apenas "working" sem dizer **o quê**.

**Mudança:** novo campo derivado em-memory `currentAction: string | null` por agente. Não persiste no DB (efêmero por turn).

**Onde vive:**
- Adapter mantém `currentAction` interno (atualizado em `parseStreamLine`)
- `AgentAdapter.getCurrentAction()` retorna a string (interface já prevista no PR-A)
- IPC broadcast novo `AGENT_CURRENT_ACTION_CHANGED` (granular, debounced 200ms — evita flood)
- Renderer store guarda `currentActions: Map<agentId, string | null>` separado do roster

**Mapping tool → string:**
| Tool detected | Display |
|---|---|
| `Read` | `Reading {basename do path}` |
| `Edit` / `Write` / `MultiEdit` | `Editing {basename}` |
| `Bash` | `Running shell` (não vaza comando — security per memory `feedback_security_priority`) |
| `Glob` / `Grep` | `Searching` |
| `mcp__dashboard__*` | `Talking to dashboard` |
| Permission pending (qualquer) | `Waiting for permission ({tool name})` |
| Após `result` event do turn | `null` (cleared) |

**UI:**
- Sidebar `AgentRosterItem`: quando status = `working`/`thinking`, mostra linha extra italica com `currentAction`

### C.2 Granular IPC events (delta, não snapshot)

Hoje `AGENT_EVENT` broadcast manda **roster completo** a cada turn-complete (lição M6.1 — stderr inviável). Renderer re-fetch tudo. Caro em re-render.

**Refactor:** discriminated union por kind. Renderer aplica delta no store.

```ts
// packages/shared/src/ipc-channels.ts
export type AgentEventDelta =
  | { kind: 'status-changed'; agentId: string; status: AgentStatus; updatedAt: number }
  | { kind: 'current-action-changed'; agentId: string; action: string | null }
  | { kind: 'session-id-changed'; agentId: string; sessionId: string | null }
  | { kind: 'roster-changed'; companyId: string };
  // 'roster-changed' = hire/fire/role-change/reports_to → renderer re-fetch agents.list()
```

**Renderer store handlers:**
```ts
// apps/renderer/src/stores/agents.ts
ipc.on('AGENT_EVENT', (delta: AgentEventDelta) => {
  switch (delta.kind) {
    case 'status-changed':       patchAgent(delta.agentId, { status: delta.status }); break;
    case 'current-action-changed': setCurrentAction(delta.agentId, delta.action); break;
    case 'session-id-changed':   patchAgent(delta.agentId, { claudeSessionId: delta.sessionId }); break;
    case 'roster-changed':       fetchRoster(delta.companyId); break;
  }
});
```

**Test regression-guard:** snapshot test verifica que `AGENT_EVENT` payload em `status-changed` é < N bytes (delta pequeno) — não cresce pra snapshot completo acidentalmente.

### C.5 SECURITY.md update

Adicionar 3 seções:

**§ Architectural decisions**
- Blocklist `§8.3` permanece em `gate.ts` mesmo após adapter remoto chegar
- Razão: defense-in-depth (Docker isolation + command filter > Docker isolation only)
- Documentar trade-off: 2 camadas é overhead mas pega bypass de Docker (ex: container escape via mount, missing namespaces no host kernel)

**§ Adapter threat models**
- `claude-oauth-local`: same-machine, OAuth credentials shared from host keychain. Threat: agent escapes sandbox CWD/CLAUDE_CONFIG_DIR via Bash + abs paths. Mitigation: gate.ts blocklist + `--strict-mcp-config` + per-agent settings.json
- `claude-api-key-local` (M9 futuro): same-machine, API key via env. Threat: same. Mitigation: same + redact API key from logs
- `claude-oauth-remote-docker` (M10 futuro): different machine, OAuth credentials forwarded via secure channel. Threat: WSS interception, Docker escape, host network access. Mitigation: WSS with mutual TLS, Docker isolation, network policy restricting outbound

**§ Approvals & artifacts (foundation)**
- Storage de approvals e artifacts não persiste secrets (gitleaks scan no pre-push pega vazamentos acidentais)
- `record_artifact.preview` é capped em 4KB
