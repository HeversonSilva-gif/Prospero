## Decisões resolvidas (brainstorming 2026-05-14)

| # | Decisão | Justificativa |
|---|---------|---------------|
| 1 | **Escopo full M9** (A+B+C+D+E+F) | User escolheu fechar v1 antes de pivotar pra V2. Não deixar wishlist pra outra milestone. |

| 6 | **Auto-restart main via `app.relaunch()`** | Pattern Electron oficial. 5s timeout de log emergency. Não tentar self-heal — relaunch é definitivo. |
| 7 | **Spec único + plans separados por PR** | Padrão M8.5/M8.6. Este doc cobre design completo; writing-plans gera 6 plans focados. |

**Migration 0016** (já listada).

**Adapter novo** `apps/main/src/orchestrator/adapters/claude-api-key-local/`:
- `adapter.ts` — implementa `AgentAdapter`. Difere de `claude-oauth-local` apenas em:
  1. **Env**: passa `ANTHROPIC_API_KEY=<decrypted>` em vez de copiar `.credentials.json`.
  2. **CLAUDE_CONFIG_DIR**: ainda isolado per-agent (mesma lógica do M3).
  3. **`--strict-mcp-config`**: continua ativo.
- Reusa `prepare-sandbox.ts`, `build-args.ts`, `stream-parser.ts`, `resolve-binary.ts` do oauth-local — se possível, factor out shared logic em `adapters/common/`.

**Registry update** `adapters/index.ts`:
```typescript

```

**`auth-mode.ts`** (M7.5 stub):
```typescript
export const getAuthMode = (settings: AppSettings): 'oauth' | 'api-key' =>
  settings.authMode;
```

**IPC novo** `auth:api-key-set(key: string)`:
- Valida formato (`/^sk-ant-[a-zA-Z0-9-]{40,}$/`).
- `safeStorage.encryptString(key)` → grava em `userData/api-key.bin`.
- Broadcast `auth:api-key-status-changed`.

**IPC novo** `auth:api-key-status` → `{ hasKey: boolean }` (nunca retorna o blob).

**Spawn pipeline:**
- Quando agente é criado, `agents.adapter_name = authMode === 'oauth' ? 'claude-oauth-local' : 'claude-api-key-local'`.
- `lifecycle.spawn()` lê `agent.adapter_name` e despacha pro factory correto via `createAdapter(name, ctx)`.

**4-agent cap update:**
```typescript
const activeCount = countActive(companyId);
if (settings.authMode === 'oauth' && activeCount >= 4) {
  throw new Error('OAuth Max ToS: máx 4 agentes simultâneos. Trocar pra API key remove o cap.');
}
```

## 8. PR-E — Error handling §7

### 8.1 Banner global vermelho (OAuth invalid)

**Componente** `apps/renderer/src/components/banners/AuthErrorBanner.tsx`:
- Hook `useAuthStore(s => s.status)` — quando `status.kind === 'invalid'`, mostra banner full-width.
- Click "Reconectar" abre `/setup`.

### 8.2 Auto-restart main em crash

**`apps/main/src/main.ts`** handler:
```typescript
process.on('uncaughtException', (err) => {
  logEmergency(err);  // write to userData/emergency.log
  setTimeout(() => {
    app.relaunch();
    app.exit(0);
  }, 5000);  // 5s pra log finalizar + chance de salvar pending state
});
```

### 8.3 Backoff exponencial em rate limit

**Stream parser** `apps/main/src/orchestrator/adapters/.../stream-parser.ts`:
- Detecta `rate_limit_exceeded` event do API.
- Emit `'rate-limit'` event up pro lifecycle.
- Lifecycle pausa agente (`status='waiting'`), agenda retry com backoff `2^n * 1s` (max 60s).
- Banner amarelo via broadcast `auth:rate-limited`.

### 8.4 Heartbeat agent

**Background worker** em `apps/main/src/orchestrator/heartbeat.ts`:
- Cada 1min, varre agentes com `status='working'`.
- Pra cada, checa `activity_events` mais recente daquele agentId.
- Se >5min sem evento → marca `status='error'`, envia inbox kind `agent_unresponsive`, broadcast.
- UI: card do agente ganha botão "Reiniciar" (chama `lifecycle.terminate()` + `lifecycle.spawn()`).

**Inbox kind novo:** `agent_unresponsive` em `packages/shared/src/types/inbox.ts`.

### 8.5 Tests (~6)

- AuthErrorBanner renders quando status=invalid.
- Heartbeat: simulate 5min sem activity → marks error + emits inbox.
- Backoff: rate-limit event → backoff schedule correto.
- Auto-restart logic (mock `app.relaunch`).
