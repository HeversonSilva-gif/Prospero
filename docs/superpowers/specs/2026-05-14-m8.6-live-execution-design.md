# M8.6 — Live Execution & Kanban Collab — Implementation design

> **Data:** 2026-05-14
> **Tipo:** Implementation design doc
> **Status:** Brainstorming aprovado em 2026-05-14
> **Predecessor:** [M8.5 Goals + CEO Planning](./2026-05-12-m8-5-goals-implementation-design.md) — atomic foundation
> **Base canônica:** [paperclip-gaps-ux-governance-design.md §2.3](./2026-05-11-paperclip-gaps-ux-governance-design.md) — design alto nível

---

## TL;DR

M8.5 entregou Goals + CEO planning + executor **atômico** (1 transaction SQLite, silenciosa). M8.6 adiciona um modo **narrated**: o CEO entra num turn dedicado, emite MCP calls em sequência streamada (`hire_agent_for_plan` → `create_issue_for_plan` → `comment_on_issue(rationale)` → `finalize_goal_execution`), e o user vê o kanban "ganhando vida" em tempo real. Atomic permanece como **default**; narrated é **opt-in** via Settings global (`executorMode`) ou toggle per-goal no `GoalPlanReview`.

**Split:** PR-A backend (~4 dias) + PR-B UI (~2-3 dias). Estimativa total **6-7 dias**, ~110-125 testes novos.

---

## Decisões resolvidas (brainstorming 2026-05-14)

| # | Decisão | Justificativa |
|---|---------|---------------|
| 1 | **Default = atomic, narrated opt-in** | Tokens não podem inflar ([[feedback_token_efficiency]]). Narrated 2-3x custo por approve. Reversibilidade: atomic é baseline conhecido. |
| 2 | **Flag location**: Settings global + override per-goal | `Settings.executorMode='atomic'\|'narrated'` define default. `GoalPlanReview` tem checkbox inline que override pro approve atual. |
| 3 | **`comment_on_issue` sender**: qualquer agente + sanitizer | `sender_id = ctx.agentId` sem restrição. Sanitizer M5 anti-injection aplicado. CEO comenta rationale, assignee comenta progresso, observador comenta review. |
| 4 | **Topo activation trigger**: hook no IPC `issues:update` quando `status='done'` | Piggyback no path existente (`issues-handlers.ts:43`). Sem watcher background, sem SQL trigger. Simples e debugável. |
| 5 | **Loop end signal**: MCP tool dedicada `finalize_goal_execution` | Determinístico. Sem heurística "turn-complete sem MCP calls" (race-prone). Sem max-turns timeout (frustrante). |
| 6 | **State persistence narrated**: `goals.execution_state_json` (DB column) | Sobrevive crash. Boot recovery oferece "Retomar narrado" / "Rollback atomic". Sem auto-retry (agent state pode ter mudado). |
| 7 | **Topo activation aplica só a plan-driven issues** | `issues.depends_on_json` populado apenas via `create_issue_for_plan` (narrated) ou executor atomic ressubscript (M8.5 já faz). Issue criada via UI manual = `depends_on_json` NULL = wake imediato (M5 preservado). |
| 8 | **Sem inbox kind novo** | `issue_comment_mention` (@-mention) deferido pra v2. Reusa `goal_executing` + `goal_error` (já existentes em M8.5 PR-B). |
| 9 | **PR split**: PR-A backend + PR-B UI (padrão M8.5) | Smoke entre PRs. Familiar pro projeto. |

## 1. Arquitetura macro

```
┌──── M8.5 (preservado, default) ────────────────────────────────┐
│ IPC goals:approve-plan → executePlanAtomic(db, opts)           │
│   ↓ SQLite trans (hire+create silencioso)                       │
│ broadcast agents:list-changed + issues:list-changed             │
│ + inbox.goal_executing                                          │
└────────────────────────────────────────────────────────────────┘

┌──── M8.6 (opt-in, narrated mode) ──────────────────────────────┐
│ IPC goals:approve-plan {mode:'narrated'}                        │
│   ↓ executePlanNarrated(db, ceo)                                │
│ goalsRepo.updateStatus → 'approved'                             │
│ goalsRepo.setExecutionState({agentIndexToId:{},                 │
│                              issueIndexToId:{}, step:'starting'})│
│   ↓                                                             │
│ router.enqueue(CEO, '[GOAL_EXECUTE_REQUEST]', system)          │
│   ↓ CEO turn (narrated system prompt block injected)            │
│                                                                  │
│ CEO loop (multi-turn, streamed):                                │
│   hire_agent_for_plan({planIndex}) →                            │
│     state.agentIndexToId[idx] = newAgentId, persist             │
│   create_issue_for_plan({planIndex}) →                          │
│     resolve assignee + depends_on_json via state, persist       │
│   comment_on_issue({issueId, comment}) →                        │
│     sanitizer + insert + broadcast                              │
│   ...                                                            │
│   finalize_goal_execution({goalId}) →                           │
│     validate complete, goal.status='in_progress',               │
│     clear state, inbox.goal_executing, broadcast                │
│   ↓                                                             │
│ Post-execution (per-issue, async):                              │
│   issues:update status='done' (handler hook)                   │
│   → check depends_on_json of dependents                         │
│   → notifyAssignee waves of newly unlocked                      │
│   + activity issue.unlocked_by_deps                             │
└────────────────────────────────────────────────────────────────┘
```

## 2. Schema (Migration 0014)

```sql
PRAGMA defer_foreign_keys = 1;

ALTER TABLE goals ADD COLUMN execution_state_json TEXT;
-- JSON shape:
--   {
--     "planId": "plan_xxx",
--     "mode": "narrated",
--     "includeAgentIndexes": [0,1,2] | null,
--     "includeIssueIndexes": [0,1,2,3,4] | null,
--     "agentIndexToId": { "0": "ag_xxx", "1": "ag_yyy" },
--     "issueIndexToId": { "0": "iss_xxx" },
--     "step": "hiring" | "creating_issues" | "commenting" | "finalizing",
--     "startedAt": 1716345600000,
--     "ceoId": "ag_ceo"
--   }
-- Null = goal não está em execução narrated. Cleared no finalize.

ALTER TABLE issues ADD COLUMN depends_on_json TEXT;
-- JSON array de issue.id (não plan indexes — resolvidos no momento da criação).
-- Null = sem deps (user-criada manual OR sem deps no plano).
CREATE INDEX idx_issues_depends_on ON issues(depends_on_json) WHERE depends_on_json IS NOT NULL;
```

**Notas:**
- `execution_state_json` updates são "best-effort durability" — escritos a cada MCP call do narrated loop. Se app crash entre call e write, perde último step mas state anterior sobrevive.
- `depends_on_json` é LIKE-searchable (string match) ou cacheável em memória pelo handler. JSON1 extension não é assumida (better-sqlite3 com WAL).

## 4. Executor dispatcher

`apps/main/src/goals/executor.ts` (edit do M8.5):

```ts
export type ExecutePlanOptions = {
  includeAgentIndexes?: Set<number>;
  includeIssueIndexes?: Set<number>;
  mode?: 'atomic' | 'narrated';
};

export const executePlan = (
  db: Database.Database,
  planId: string,
  options: ExecutePlanOptions,
  // narrated-only deps:
  narratedDeps?: {
    router: OrchestratorRouter;
    ceoId: string;
    threadId: string;
  },
): ExecuteResult => {
  const mode = options.mode ?? settingsRepo.getExecutorMode() ?? 'atomic';
  if (mode === 'narrated' && narratedDeps !== undefined) {
    return executePlanNarrated(db, planId, options, narratedDeps);
  }
  return executePlanAtomic(db, planId, options); // M8.5 code unchanged
};
```

**`executePlanAtomic` é o código atual do M8.5** renomeado (zero refactor).

**Wiring dos `narratedDeps`:** seguindo lição M8.5 PR-A ([[project_m8_5_pr_a_lessons]] §6), router + ceoId resolution vivem em closures de `registerOrchestratorHandlers(db)`. O `GoalsOrchestrator` type já passado a `goalsHandlers(deps)` ganha 1 método novo:

```ts
export type GoalsOrchestrator = {
  deliverSystemMessage: (agentId: string, text: string) => void;
  // NEW for M8.6:
  enqueueExecuteRequest: (ceoId: string, prompt: string) => { threadId: string };
};
```

`enqueueExecuteRequest` usa `messages.ensureThread(companyId, ['user', ceoId])` + `router.enqueue(...)`, retornando threadId pra `executePlanNarrated` persistir em state se necessário.

`executePlanNarrated` em arquivo novo `apps/main/src/goals/executor-narrated.ts`:
1. Resolve plan + goal, valida `plan.status='proposed'` e `goal.status='proposed'`.
2. `goalsRepo.updateStatus(goalId, 'approved')`.
3. `goalsRepo.setExecutionState(goalId, { planId, mode:'narrated', includeAgentIndexes, includeIssueIndexes, agentIndexToId:{}, issueIndexToId:{}, step:'starting', startedAt:Date.now(), ceoId })`.
4. `router.enqueue(ceoId, threadId, formatGoalExecuteRequest(goal, plan), { kind:'user', id:null, name:'System' })`.
5. Return `{ok:true, executionStarted:true, hiredAgentIds:[], createdIssueIds:[]}` imediato — wake-ups acontecem assíncronos.

`formatGoalExecuteRequest(goal, plan)` (novo, ao lado de `formatGoalPlanRequest`):
```
[GOAL_EXECUTE_REQUEST]
goalId={id}
planId={planId}
mode=narrated

Execute your proposed plan v{version} for "{goal.title}" by emitting MCP calls
in sequence. Available tools for this loop:
- hire_agent_for_plan(planIndex) — instantiate plan.agentsToHire[N]
- create_issue_for_plan(planIndex) — instantiate plan.issuesToCreate[N]
- comment_on_issue(issueId, comment) — add narration to an issue you created
- finalize_goal_execution(goalId) — close the loop when all items are done

Convention:
1. Hire agents in topological order (respect reportsToIndex chain).
2. Create issues in topological order (respect dependsOnIndexes).
3. After each create_issue_for_plan, optionally add a brief comment_on_issue
   explaining the rationale and what comes next.
4. When ALL hires and issues are processed, call finalize_goal_execution.
5. If you encounter an error, decide: retry, skip, or call
   finalize_goal_execution({abort:true}) to roll back.

Plan summary:
{plan.summary}

Agents to hire ({plan.agentsToHire.length}):
{numbered list of agentsToHire with index, name, role, reportsToIndex}

Issues to create ({plan.issuesToCreate.length}):
{numbered list of issuesToCreate with index, title, assigneeIndex, dependsOnIndexes}
```

### 5.1 `comment_on_issue` (novo, `apps/main/src/mcp/tools-issues.ts`)

```ts
{
  name: "comment_on_issue",
  description: "Add a comment to an issue. Sender = current agent. Sanitizer applied.",
  inputSchema: z.object({
    issueId: z.string(),
    comment: z.string().min(1).max(5000),
  }),
  run: async (input, ctx) => {
    const { issueId, comment } = parse(input);
    const issuesRepo = createIssuesRepository(ctx.db);
    const issue = issuesRepo.getById(issueId);
    if (!issue || issue.companyId !== ctx.companyId) {
      throw new Error(`issue ${issueId} not found`);
    }
    const sanitized = sanitizeUserContent(comment); // reuse M5 sanitizer
    const commentRow = issuesRepo.addComment(issueId, sanitized, {
      authorAgentId: ctx.agentId,
    });
    recorder?.recordActivity({
      companyId: ctx.companyId,
      actor: { kind: 'agent', id: ctx.agentId },
      action: 'issue.commented',
      entityKind: 'issue',
      entityId: issueId,
      agentId: ctx.agentId,
      payload: { commentId: commentRow.id, length: sanitized.length },
    });
    broadcast('issues:changed', { kind:'comment-added', issueId, companyId: ctx.companyId });
    return JSON.stringify({ commentId: commentRow.id, createdAt: commentRow.createdAt });
  },
}
```

### 5.2 `hire_agent_for_plan` (novo, `tools-goals.ts` edit)

```ts
{
  name: "hire_agent_for_plan",
  description: "Hire one agent from the current plan's agentsToHire by index. Idempotent: returns existing id if already hired.",
  inputSchema: z.object({ planIndex: z.number().int().min(0) }),
  run: async (input, ctx) => {
    const { planIndex } = parse(input);
    const goalsRepo = createGoalsRepository(ctx.db);
    // Find goal currently in narrated execution where ctx.agentId is the ceoId.
    const goal = goalsRepo.findActiveNarratedByCeo(ctx.agentId);
    if (goal === null) throw new Error('no active narrated execution for this agent');
    const state = JSON.parse(goal.execution_state_json) as ExecutionState;
    const plansRepo = createGoalPlansRepository(ctx.db);
    const plan = plansRepo.getById(state.planId);
    if (!plan) throw new Error('plan not found');
    const agentSpec = plan.agentsToHire.find(a => a.index === planIndex);
    if (!agentSpec) throw new Error(`planIndex ${planIndex} not in agentsToHire`);
    if (state.includeAgentIndexes !== null && !state.includeAgentIndexes.includes(planIndex)) {
      throw new Error(`planIndex ${planIndex} excluded by filter`);
    }
    // Idempotent
    if (state.agentIndexToId[planIndex] !== undefined) {
      return JSON.stringify({ agentId: state.agentIndexToId[planIndex], existing: true });
    }
    // Resolve reportsTo
    let reportsToId: string;
    if (agentSpec.reportsToIndex === 'CEO') {
      reportsToId = state.ceoId;
    } else {
      const resolved = state.agentIndexToId[agentSpec.reportsToIndex];
      if (resolved === undefined) {
        throw new Error(`reportsToIndex ${agentSpec.reportsToIndex} not yet hired`);
      }
      reportsToId = resolved;
    }
    const agentsRepo = createAgentsRepository(ctx.db, recorder);
    const created = agentsRepo.create({
      companyId: ctx.companyId,
      name: agentSpec.name,
      role: agentSpec.roleTemplateId,
      systemPrompt: agentSpec.personaSummary,
      mode: 'supervised',
      alwaysOn: false,
      model: agentSpec.model,
      skills: agentSpec.skills,
      templateId: agentSpec.roleTemplateId,
    });
    agentsRepo.setReportsTo(created.id, reportsToId);
    state.agentIndexToId[planIndex] = created.id;
    state.step = 'hiring';
    goalsRepo.setExecutionState(goal.id, state);
    recorder?.recordActivity({
      companyId: ctx.companyId,
      actor: { kind: 'agent', id: ctx.agentId },
      action: 'goal.narrated_step',
      entityKind: 'goal',
      entityId: goal.id,
      agentId: ctx.agentId,
      payload: { step: 'hire', planIndex, agentId: created.id },
    });
    broadcast('agents:list-changed', { hiredAgentIds: [created.id] });
    return JSON.stringify({ agentId: created.id, name: created.name });
  },
}
```

### 5.4 `finalize_goal_execution` (novo, `tools-goals.ts` edit)

```ts
{
  name: "finalize_goal_execution",
  description: "Close the narrated execution loop. Validates all plan items are processed (or aborts cleanly).",
  inputSchema: z.object({
    goalId: z.string(),
    abort: z.boolean().optional(),
  }),
  run: async (input, ctx) => {
    const { goalId, abort } = parse(input);
    const goalsRepo = createGoalsRepository(ctx.db);
    const goal = goalsRepo.getById(goalId);
    if (!goal || goal.companyId !== ctx.companyId) {
      throw new Error('goal not found');
    }
    if (goal.execution_state_json === null) {
      throw new Error('goal has no active execution');
    }
    const state = JSON.parse(goal.execution_state_json) as ExecutionState;
    const plansRepo = createGoalPlansRepository(ctx.db);
    const plan = plansRepo.getById(state.planId);
    if (!plan) throw new Error('plan not found');

    if (abort === true) {
      // Rollback in a single SQLite transaction (order matters: issues before agents
      // because issues.assignee_id FK references agents.id).
      db.transaction(() => {
        for (const id of Object.values(state.issueIndexToId)) {
          issuesRepo.delete(id);
        }
        for (const id of Object.values(state.agentIndexToId)) {
          agentsRepo.delete(id);
        }
        plansRepo.markRejected(plan.id, 'aborted by CEO during narrated execution');
        goalsRepo.updateStatus(goalId, 'cancelled');
        goalsRepo.setExecutionState(goalId, null);
      })();
      return JSON.stringify({ aborted: true });
    }

    // Validate complete
    const expectedAgents = state.includeAgentIndexes ?? plan.agentsToHire.map(a => a.index);
    const expectedIssues = state.includeIssueIndexes ?? plan.issuesToCreate.map(i => i.index);
    const missingAgents = expectedAgents.filter(i => state.agentIndexToId[i] === undefined);
    const missingIssues = expectedIssues.filter(i => state.issueIndexToId[i] === undefined);
    if (missingAgents.length > 0 || missingIssues.length > 0) {
      throw new Error(
        `incomplete: missingAgents=${JSON.stringify(missingAgents)}, missingIssues=${JSON.stringify(missingIssues)}`
      );
    }

    plansRepo.markApproved(plan.id, { decidedBy: 'ceo-narrated' });
    goalsRepo.updateStatus(goalId, 'in_progress');
    goalsRepo.setExecutionState(goalId, null);

    const hiredAgentIds = Object.values(state.agentIndexToId);
    const createdIssueIds = Object.values(state.issueIndexToId);

    inboxRepo.create({
      companyId: ctx.companyId,
      kind: 'goal_executing',
      title: `Plan for "${goal.title}" is executing`,
      preview: `${hiredAgentIds.length} agents hired, ${createdIssueIds.length} issues created (narrated)`,
      payloadJson: JSON.stringify({ goalId, planId: plan.id }),
      requiresAction: false,
    });
    broadcast(IPC.INBOX_UPDATE, { companyId: ctx.companyId });

    recorder?.recordActivity({
      companyId: ctx.companyId,
      actor: { kind: 'agent', id: ctx.agentId },
      action: 'goal.plan_approved',
      entityKind: 'goal',
      entityId: goalId,
      agentId: ctx.agentId,
      payload: { planId: plan.id, version: plan.version, hiredAgentIds, createdIssueIds, approvedBy: 'ceo-narrated' },
    });

    return JSON.stringify({ ok: true, hiredAgentIds, createdIssueIds });
  },
}
```

## 6. Topological activation (post-execution)

`apps/main/src/ipc/issues-handlers.ts` edit no handler `ISSUES_UPDATE`:

```ts
ipcMain.handle(IPC.ISSUES_UPDATE, async (_e, args) => {
  const before = issuesRepo.getById(args.id);
  const updated = issuesRepo.update(args);
  if (updated === null) return null;

  // Existing notify path
  if (args.assigneeId !== undefined && args.assigneeId !== before?.assigneeId) {
    notifyAssignee(updated);
  }

  // NEW: topological unlock
  if (before?.status !== 'done' && updated.status === 'done') {
    const dependents = issuesRepo.findDependentsOf(updated.id); // SELECT WHERE depends_on_json LIKE '%<id>%'
    for (const dep of dependents) {
      if (dep.status !== 'todo') continue; // already moving or done
      const depIds = JSON.parse(dep.depends_on_json) as string[];
      const allDone = depIds.every(id => {
        const d = issuesRepo.getById(id);
        return d?.status === 'done';
      });
      if (allDone) {
        notifyAssignee(dep);
        recorder?.recordActivity({
          companyId: dep.companyId,
          actor: { kind: 'system' },
          action: 'issue.unlocked_by_deps',
          entityKind: 'issue',
          entityId: dep.id,
          payload: { unlockedBy: updated.id },
        });
      }
    }
  }

  return updated;
});
```

**`findDependentsOf(issueId: string)`** novo método em `issuesRepository`:
```ts
SELECT * FROM issues
WHERE depends_on_json IS NOT NULL
  AND depends_on_json LIKE '%' || ? || '%'
  AND company_id = ?
```
(Falsos positivos por substring match são filtrados pelo parse JSON do handler.)

## 7. Boot recovery

`apps/main/src/goals/recovery.ts` edit (extend M8.5 recovery scan):

```ts
// Detect goals stuck in narrated execution (app crash mid-loop)
const stuckNarrated = goalsRepo.findStuckNarrated(); // status='approved' AND execution_state_json IS NOT NULL
for (const goal of stuckNarrated) {
  const state = JSON.parse(goal.execution_state_json) as ExecutionState;
  inboxRepo.create({
    companyId: goal.companyId,
    kind: 'goal_error',

      goalId: goal.id,
      planId: state.planId,
      step: 'narrated_halted',
      hiredCount: Object.keys(state.agentIndexToId).length,

    }),
    requiresAction: true,
  });
}
broadcast(IPC.INBOX_UPDATE, ...);
```

Recovery actions são exposed via 2 IPCs novos:
- `goals:narrated-resume` — resume CEO turn com `[GOAL_EXECUTE_RESUME] state=...`
- `goals:narrated-rollback` — chama `finalize_goal_execution({abort:true})` internamente (sem CEO involvement)

## 8. Failure modes (consolidado)

| Modo | Comportamento |
|---|---|
| CEO max-turns hit no meio do loop | Loop trava. `goal.status='approved'`, `execution_state_json` present. Boot recovery (próxima boot OR on-demand) cria inbox `goal_error` com payload step=`narrated_halted`. User: "Retomar narrado" (re-enqueue CEO) OR "Rollback atomic" (finalize_goal_execution abort). |
| MCP call retorna erro de validação (assignee_not_hired, dep_not_created) | Tool retorna `{error}` estruturado. CEO recebe no próximo turn, decide retry, skip, ou abort. Sem state corruption (writes são atomic per-call). |
| App crash mid-loop | `execution_state_json` em DB sobrevive. Mesma path do max-turns. |
| Retry idempotente | Cada `*_for_plan` checa `state[idx]` antes de inserir. Returns existing id se já criado. |
| `finalize_goal_execution` antes de completar | Tool retorna `{error:'incomplete', missingAgents, missingIssues}`. CEO chama os faltantes e tenta de novo. |
| `finalize_goal_execution({abort:true})` | Rollback: delete agents/issues criados, plan→rejected, goal→cancelled, clear state. |
| Topo activation com false-positive em LIKE | `findDependentsOf` retorna candidates por substring; handler parse JSON e descarta falsos. Idempotente. |

## 14. Riscos + mitigações

| Risco | Mitigação |
|---|---|
| CEO max-turns hit antes de finalize | State persistido → recovery oferece resume / rollback |
| CEO chama tools fora de ordem (assignee antes de hire) | Tools retornam erro estruturado, CEO se auto-corrige no próximo turn |
| Comentários narrados viram ruído no kanban | Sender badge separa visualmente; ativar narrated é opt-in |
| Token cost explode com plano grande | Settings opt-in + token comparison visível no GoalPlanReview antes do approve |
| `findDependentsOf` LIKE retorna false-positives | Handler parse JSON e descarta — idempotente |
| Concorrência: 2 goals em execução narrada simultâneos | `findActiveNarratedByCeo` retorna 1; CEO só pode estar em 1 loop. Se 2nd approve narrated chega enquanto outro está ativo → tool returns error `another_execution_active` |
| Migration 0014 em DB com `goals` populados | Columns ADD são NULL pra rows existentes → backward compatible |

## Apêndice B — State machine de Goal (atualizada)

```
draft ──────────────────┐
  │                     ↓
  ↓ requestPlan       cancelled
planning ─────────────► (terminal)
  │
  ↓ submit_goal_plan
proposed ──────────────┐
  │ approve            │ reject
  ↓                    ↓
approved              cancelled
  │
  ↓ (atomic: synchronous · narrated: async via CEO loop)
in_progress
  │
  ↓ (manual via update_goal_status)
achieved | cancelled
```

Estado `approved` é o único que pode ter `execution_state_json` populado (narrated em curso). Recovery scan procura especificamente `status='approved' AND execution_state_json IS NOT NULL`.
